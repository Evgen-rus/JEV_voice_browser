# voice-browser --- говорите с настоящим браузером, и он действует ещё до того, как вы закончите фразу

Node-приложение, которое голосом управляет **видимым окном Chromium**
через Playwright. Речь передаётся слово за словом из Web Speech API
браузера на небольшой Node-сервер; при каждом промежуточном транскрипте
сервер одним запросом задаёт **Jev** (модели System One от TypeSafe,
`jev-1.13.0`) около десятка типизированных вопросов --- намерение,
целевой элемент, сайт, «команда завершена?», «эта фраза вообще
адресована мне?», «действие разрушительное?» --- получает типизированные
вероятности примерно за 250--350 мс, после чего код решает: выполнить
действие, подождать, уточнить или проигнорировать.

Jev никогда не генерирует текст. Поисковые запросы, вводимый текст и URL
код извлекает как возможные фрагменты, а Jev только *выбирает* один из
них, который затем копируется дословно.

``` text
 микрофон (Chrome, Web Speech API)       Node-сервер (хранит API-ключ)              управляемое окно
 ────────────────────────────────   ws   ───────────────────────────────────         ──────────────────
 промежуточные транскрипты ────────────▶ debounce 200 мс                            видимый Chromium через
 "go to"  "go to wiki"                   снимок страницы (≤100 элементов, e01..eNN) ◀── Playwright, постоянный
 "go to wikipedia" (final)               ОДИН запрос Jev: 9–11 вопросов              профиль, overlay
                                         policy (пороги в constants.js)       ───▶  подсветка / toast /
 страница управления ◀────────────────── решение + полосы + задержка + цена           пронумерованные кандидаты
```

## Запуск

Требования: Node ≥ 20 (протестировано на 22), npm, Chrome или Edge для
микрофона (Web Speech API недоступен в Firefox/Safari). Реальные
API-вызовы стоят около \$0.0002 каждый.

``` bash
git clone https://github.com/moritzkremb/jev-voice-browser.git
cd jev-voice-browser
npm install
npx playwright install chromium
cp .env.example .env          # вставьте API-ключ TypeSafe (https://console.typesafe.ai/keys)
./run.sh                      # запускает сервер на http://localhost:8787
```

Затем откройте **http://localhost:8787 в обычном Chrome**, нажмите
**Start mic**, разрешите доступ к микрофону и говорите. Сервер откроет
отдельное окно Chromium --- *управляемый* браузер. Именно в нём
выполняются действия. Держите страницу управления на втором мониторе или
на половине экрана, чтобы видеть полосы вероятностей в реальном времени.

Параметры: `./run.sh --port 9000`, `--host 0.0.0.0` (LAN, см. раздел
«Безопасность»), `--start-url https://…`, `--headless` (CI). Также можно
подключиться к уже запущенному Chrome вместо запуска нового:

``` bash
# запустите Chrome с портом отладки, затем:
./run.sh --cdp http://127.0.0.1:9222
```

Вместо `.env` ключ можно задать самостоятельно:
`export TYPESAFE_API_KEY=…` (устаревший `JEV_API_KEY` тоже
поддерживается), затем выполнить `npm start`. Ключ читает только
Node-процесс; страница управления его никогда не получает.

**Безопасность:** сервер слушает только `127.0.0.1`. Любой, кто имеет
доступ к порту управления, может управлять браузером и расходовать ваши
API-кредиты, поэтому используйте `--host 0.0.0.0` только в доверенной
сети. Управляемый Chromium использует постоянный профиль в
`.browser-profile/` (он исключён через gitignore) --- не входите там в
аккаунты, в которых ошибочно распознанная команда вроде «click place
order» может привести к нежелательному действию. Для разрушительных
кликов требуется голосовое подтверждение «confirm», но воспринимайте это
как дополнительное удобство, а не как гарантию безопасности.

Нет микрофона? Введите команду в текстовое поле на странице управления и
нажмите Enter.

## Как принимается решение

Каждое обновление транскрипта создаёт ровно один запрос к Jev
(`src/jev.js`). Состояние:

``` json
{ "transcript": "click the first result",
  "page": { "url": "...", "title": "...", "site": "duckduckgo" },
  "elements": ["e02 combobox \"jev typesafe\" (placeholder: Search privately)", "e20 link \"TypeSafe — Jev\" → typesafe.ai", "..."] }
```

Вопросы (все находятся в `src/constants.js`, задаются вместе и
обрабатываются параллельно):

  -----------------------------------------------------------------------------
  id                      тип                     ответы
  ----------------------- ----------------------- -----------------------------
  `intent`                Choice                  navigate_url · search_web ·
                                                  click_element ·
                                                  type_into_field ·
                                                  select_option · press_enter ·
                                                  scroll_down/up ·
                                                  go_back/forward · reload ·
                                                  open/close/switch tab ·
                                                  confirm · cancel · none ---
                                                  каждый вариант содержит
                                                  `{what, not_for, examples}`

  `target`                Choice                  ID элементов на странице +
                                                  `none`

  `site`                  Choice                  google · duckduckgo · the_web
                                                  · youtube · wikipedia ·
                                                  github · amazon · reddit ·
                                                  twitter_x · hacker_news ·
                                                  example_com ·
                                                  other_named_site · none

  `complete`              Noul                    закончил ли пользователь
                                                  команду? (позволяет
                                                  действовать по незавершённой
                                                  речи)

  `is_command`            Noul                    обращается ли пользователь
                                                  вообще к браузеру?

  `destructive`           Noul                    приведёт ли действие к
                                                  отправке / покупке / удалению
                                                  / пересылке?

  `scroll_amount`         Score                   немного · одна страница · до
                                                  конца

  `text_span`             Choice                  дословные
                                                  фрагменты-кандидаты,
                                                  извлечённые regex (+ `none`)
                                                  --- только если в транскрипте
                                                  они есть

  `url_span`              Choice                  фрагменты, похожие на домены
                                                  (+ `none`) --- только если
                                                  они присутствуют

  `tab_direction`         Choice                  next · previous · first ·
                                                  none
  -----------------------------------------------------------------------------

Политика (`src/policy.js`, пороги `T` в `constants.js`) отображается в
интерфейсе в реальном времени как таблица фильтров:

1.  `is_command ≥ 0.5`, иначе **ignore**
2.  `intent.confidence ≥ 0.55` и не `none`, иначе **wait**
3.  `complete ≥ 0.6`, либо 900 мс тишины, либо финальный результат
    распознавателя --- иначе **wait**
4.  намерения со свободным текстом (поиск / ввод) дополнительно ждут
    финального результата или 600 мс тишины, чтобы запрос никогда не
    обрезался («search for alan» против «search for alan turing»)
5.  действие формируется кодом: шаблоны URL, fallback на поле поиска,
    дословное копирование фрагмента
6.  для целей клика/ввода нужны `target.confidence ≥ 0.45` и
    максимальная вероятность ≥ 0.35; иначе 2--3 лучших кандидата
    получают пронумерованные метки на странице, а произнесённое число
    выбирает нужный вариант (без вызова модели)
7.  `destructive ≥ 0.5` для клика → **confirm** (скажите «confirm» /
    «cancel»)

Запросы могут пересекаться: одновременно выполняются до двух; более
старые отменяются через `AbortSignal`. Ответ на промежуточный транскрипт
всё ещё может привести к действию, если произнесённых слов уже
достаточно для однозначного действия из закрытого набора («go back»), но
для свободного текста такой ответ никогда не считается финальным.

## Структура проекта

``` text
src/constants.js   фиксация MODEL, пороги, тексты всех вопросов — основной файл для показа на камеру
src/jev.js         формирует состояние + вопросы, вызывает @typesafe-ai/sdk, возвращает ответы/задержку/usage/стоимость
src/spans.js       извлечение кандидатов (текстовые payload, произнесённые URL, числительные) — код, не Jev
src/snapshot.js    сборщик элементов страницы (добавляет data-vb-id), сжатие + ограничение размера, определение сайта
src/policy.js      ответы → act / wait / ignore / confirm / disambiguate с указанием причин
src/executor.js    действия Playwright + визуальная обратная связь overlay
src/browser.js     запуск видимого Chromium (постоянный профиль) или подключение через CDP; вкладки
src/overlay.js     внедряемая подсветка / toast / пронумерованные метки
src/controller.js  debounce, управление активными запросами, одно действие на высказывание, цепочки, статистика
src/server.js      Express + ws, раздаёт src/public/index.html (страница управления)
scripts/demo.js    пословное воспроизведение на реальных сайтах = end-to-end тест
test/unit/         spans, сжатие snapshot, policy (Jev замокан), controller (Jev + браузер замоканы)
test/integration/  27 реальных API-кейсов на сохранённых фикстурах страниц, выводит pass rate + latency
```

## Тесты и демо

``` bash
npm test                 # unit-тесты (без сети)
npm run test:integration # реальные вызовы Jev на фикстурах; выводит pass rate (ожидается ≥ 90%)
npm run demo             # headed-воспроизведение 16 голосовых команд на реальных сайтах, проверяет URL
npm run demo:ci          # то же самое в headless; код выхода 1 при ошибке
node scripts/demo.js --headless --only 1,2,3 --word-ms 250
```

Последние измерения (сентябрь 2026, на этой машине): интеграционные
тесты 27/27 (100%), средняя задержка Jev ≈ 330 мс (p50 ≈ 300 мс, 3--6
тыс. входных токенов на запрос; первый запрос процесса занимает около
700 мс из-за TLS-handshake), от последнего слова до решения ≈ 300 мс с
учётом debounce 200 мс, вся демонстрация ≈ \$0.01.

## Примечания и ограничения

-   Web Speech API работает только в Chrome/Edge; аудио отправляется в
    Google. Промежуточные результаты приходят пачками, поэтому эффект
    «действует до того, как вы закончили» лучше всего заметен на длинных
    фразах.
-   Одно действие на высказывание; дополнительные слова после
    выполненной команды рассматриваются как новая команда только в том
    случае, если их как минимум два.
-   Снимок элементов ограничен 100 элементами (сначала область
    видимости) и 60 символами текста на элемент --- на длинных страницах
    может потребоваться прокрутка, прежде чем команда «click ...» увидит
    элементы ниже первого экрана. Элементы внутри iframe не видны.
-   Сайты с сильной защитой от ботов (Google consent, некоторые
    поисковики в headless-режиме) могут не отображать результаты; в демо
    используются Wikipedia, example.com, Hacker News и DuckDuckGo.
-   `select_option` сопоставляет подпись варианта в коде по подстроке;
    `switch_tab` циклически переключает вкладки.
-   Пороги уверенности откалиброваны под `jev-1.13.0`; если перейдёте на
    другой алиас модели, заново проверьте `T`.

## Запуск в Windows PowerShell

Перейдите в папку проекта:

``` powershell
cd D:\My_dev_project\JEV_voice_browser
```

Откройте файл `.env` и замените placeholder на настоящий TypeSafe/JEV
API-ключ:

``` env
TYPESAFE_API_KEY=your_typesafe_api_key_here
```

Не публикуйте и не добавляйте ключ в Git.

Запустите сервер с переменными из `.env`:

``` powershell
node --env-file=.env src/server.js
```

После появления сообщения `voice-browser ready` откройте в обычном
Chrome:

``` text
http://localhost:8787
```

Нажмите **Start mic** и разрешите доступ к микрофону. Обычный Chrome
используется для распознавания речи, а Playwright откроет отдельное окно
Chromium --- голосовые команды управляют именно этим окном.

### Ошибка 401 AuthenticationError

Ошибка означает, что API-ключ отсутствует или недействителен. Если
правильный ключ уже записан в `.env`, проверьте, не задано ли старое
значение в текущей PowerShell-сессии:

``` powershell
Get-Item Env:TYPESAFE_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:TYPESAFE_API_KEY -ErrorAction SilentlyContinue
```

После этого снова запустите:

``` powershell
node --env-file=.env src/server.js
```
